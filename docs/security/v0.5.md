# NEOS Work v0.5 — Security threat model (short)

Scope: local-first / single-node daemon (`apps/server`) with optional Docker
self-host. Not a multi-tenant cloud control plane.

## Assets

| Asset | Location |
|---|---|
| API keys / tokens | SQLite settings (AES-256-GCM at rest) |
| Design project files | Project `baseDir` (sandbox) |
| Session auth token | Process memory; Docker via `NEOS_AUTH_TOKEN` |
| Tool tokens | In-memory, project-scoped |
| Import tokens | In-memory, path-bound, single-use |

## Trust boundaries

1. **Desktop / CLI / browser UI** → HTTP API with Bearer token  
2. **Agent tools** → `/api/tools/*` with tool-token (no daemon Bearer)  
3. **Outbound network** → media download, deploy, connection-test, BYOK bases  

## Controls (v0.5.20+)

| Threat | Control |
|---|---|
| Path traversal / symlink escape | `path-sandbox` realpath containment; archive rejects symlink entries |
| SSRF to metadata/private IP | Shared `lib/ssrf.ts` on outbound URL parse; deploy check-link; media image/video download host block; optional DNS private A/AAAA deny |
| Token override on tools | `assertNoScopeOverride` — body projectId/runId ≠ token → 403 |
| Host rebinding | Host allowlist; Docker `NEOS_ALLOW_ANY_HOST` only when intentionally exposed |
| Secret leakage | `maskSecret` / scrub on deploy errors; connection-test never returns bodies/keys |
| Folder import abuse | Single-use import token bound to validated path |
| Media runaway | Size/MIME clamps; stub policy off by default |

## Out of scope (v0.5)

- Multi-tenant auth / RBAC  
- Full browser web CSP product surface (pending `apps/web`)  
- Live provider e2e with real keys in CI  

## Ops notes

- Prefer reverse proxy + TLS when binding `0.0.0.0`  
- Rotate `NEOS_AUTH_TOKEN` by redeploying with a new value  
- Keep `NEOS_DATA_DIR` volume permissions private to the engine user
