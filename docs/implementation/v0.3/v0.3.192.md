## Changes

### Task 1: `CoordinatorSession` (`packages/core/src/tools/worker-spawn.ts`)

- **spawn_worker** — start child (returns `workerRunId`, status `running`)
- **await_workers** — wait for ids (timeout, per-id ok/output/error)
- **list_workers** — catalog (+ optional domain filter; respects allowlist)
- Caps: `maxSpawnedWorkers` default 4, hard 8; concurrency semaphore default 4
- Children always `mode: 'solo'` (no nested coordinators)
- Parent `AbortSignal` + `abortAll()` cascade
- Goal/inputs size caps aligned with orchestrator

### Task 2: AgentNode coordinator path

- When `mode === 'coordinator'` (config or worker default): register the three
  tools on the node ToolRegistry
- `allowedWorkerIds` from node config; `maxSpawnedWorkers` from worker
  constraints / node config
- Child runs via `runWorker` (solo) with worker.* event bridge to parent node
- **CLI skipped** in coordinator mode (built-in loop required)

### Task 3: Tests

- Core: spawn/await/list, cap, allowlist, abort, concurrency semaphore
- AgentNode: tools registered; CLI bypassed when coordinator; runChild event bridge

### Task 4: Version

- monorepo **0.3.191 → 0.3.192**
- health / server banner / web_search User-Agent / MCP client version

### Residual polish (same ship)

- Slot-wait cancel resolves a failed child result (no unhandled reject on
  `await_workers`)
- AgentNode coordinator: sanitize parent `runId`/`nodeId`; prefer node
  `maxSpawnedWorkers` when finite ≥1; trim `allowedWorkerIds`
