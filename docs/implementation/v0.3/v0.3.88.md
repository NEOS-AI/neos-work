# v0.3.88 Implementation

## Summary

(Task 8), **MediaNode/DeployNode HTTP error body truncate** (Tasks 7/8),

## Changes

### Task 1: Artifacts (Task 4)

- Cap content at 2 MiB on create / updateArtifactContent / updateArtifact
- Coerce non-string content; oversize throws clear error

### Task 2: Workspaces

- Reject `\0` / CR / LF in path on create (throw) and update (leave row unchanged)

### Task 3: Deploy (Task 8)

- Cap deploy content at 2 MiB (Vercel + Cloudflare)
- Vercel/Cloudflare result URLs via `safeDeployHostUrl`
- DeployNode: non-ok HTTP includes truncated body (500 chars)

### Task 4: MediaNode (Task 7)

- Non-ok HTTP includes truncated body (500 chars)
- Tolerate missing response `ok` in mocks; treat body `ok: false` as API error

### Task 5: Routines (Task 2)

- Schedule must be 5 fields; reject control chars on raw input
- Invalid schedule on update → null (row unchanged)

### Task 6: Revisions / agent steps / rate-limit / timezone

- `createRevision`: reject snapshots > 5 MiB
- Agent step data > 512 KiB → truncated preview JSON
- `FixedWindowRateLimiter`: clamp limit 1–10000, windowMs 1–1d (invalid → 60/60s)
- `isValidTimeZone`: blank/whitespace → false

### Task 7: Unit tests

- Artifact oversized content
- Workspace path control chars
- Deploy oversized content
- Media/Deploy HTTP error bodies
- Routine invalid schedule
- Revision oversized snapshot
- Agent step data truncate
- Rate-limit constructor clamp

### Task 8: Version

- monorepo **0.3.87 → 0.3.88**
- health / server banner / web_search User-Agent / MCP client version
