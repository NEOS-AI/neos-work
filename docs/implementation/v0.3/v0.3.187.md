## Changes

### Task 1: Shared types & schemaVersion (Breaking foundation)

- `NodeType` adds canonical **`agent`**; keeps deprecated `agent_finance` /
  `agent_coding` for pre-migrate graphs
- `Workflow`: `schemaVersion?: 1 | 2`, `primaryDomain?`, `domainPackIds?`;
  `domain` widened to pack-id `string` (DB column name unchanged — Q2)
- **`DomainWorker`** supersedes harness shape; **`AgentHarness`** = type alias
  (`@deprecated`)
- **`DomainPack`**, **`PortDef`**, **`AgentNodeConfig`**, permission /
  workspace / worker mode types
- **`WorkflowSSEEvent`**: `worker.started|progress|completed|failed`,
  `node.warning`
- Desktop `engine.ts` client types aligned; RunLogPanel renders worker rows

### Task 2: migrateWorkflowV1ToV2

- Pure helper: `packages/shared/src/migrate-workflow.ts`
  - `schemaVersion = 2`, `primaryDomain` from `domain`
  - `agent_finance` → `agent` + default `workerId: finance_analyst`
  - `agent_coding` → `agent` + default `workerId: coding_reviewer`
  - `harnessId` → `workerId` (workerId wins)
  - `provider` → `llmProvider` (llmProvider wins)
  - pack inference into `domainPackIds`
- Golden unit tests (14 cases) + barrel export smoke
- Server `rowToWorkflow` / `createWorkflow` / `updateWorkflow` always migrate
  so API responses and stored graphs normalize to v2 agent nodes

### Task 3: Runtime / editor compatibility

- `AgentNode` accepts `type: 'agent' | 'agent_finance' | 'agent_coding'`
- Resolves **`workerId` or `harnessId`**
- Executor `case 'agent'`
- Block prompt/skill path uses `new AgentNode('agent', …)`
- Preflight + WorkflowValidation treat `agent` like legacy agent types;
  workerId accepted for “missing harness” warning
- Palette: add **Agent** entry (legacy Finance/Coding agents kept)

### Task 4: Version

- monorepo **0.3.186 → 0.3.187**
- health / server banner / web_search User-Agent / MCP client version
