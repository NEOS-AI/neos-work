# v0.24.0 Implementation — Track OS keyring

## Summary

**Track OS keyring** — store the AES-256 master key (32 bytes) in the **native OS keyring** via optional Node `keytar`, alongside existing **env** / **file keychain** / **legacy** sources.

`keytar` is an **optionalDependency** of `@neos-work/server`. Native compile may fail on some platforms; install must still succeed and the server falls back to file/legacy when OS keyring is unavailable.

## Key resolution order

`NEOS_SECRETS_KEY_BACKEND` (default `auto`):

| Backend | Behavior |
|---|---|
| `auto` | `NEOS_MASTER_KEY` → **OS keychain** (if keytar usable and key present) → existing file/keychain key → **legacy** (no auto-create by default; preserves installs) |
| `env` | Require `NEOS_MASTER_KEY` (fail if missing) |
| `os` | Require OS keychain (`keytar`); **auto-create** random 32-byte key into keyring if missing |
| `file` | File keychain under data dir; **auto-create** random 32-byte key if missing |
| `legacy` | Force machine-derived key |

Sources logged as `NEOS_SECRETS_KEY_SOURCE=env|os|keychain|file|legacy` (no secret material).

### Auto order (detail)

1. **env** — `NEOS_MASTER_KEY` (hex / base64-32 / hashed string)
2. **OS keychain** — `OsKeychain` via optional `keytar` when the module loads; empty key does **not** auto-create under `auto` (falls through)
3. **File keychain** — `{NEOS_DATA_DIR}/.secrets/master.key` (or injected DI keychain)
4. **legacy** — `SHA-256(hostname:homedir:neos-work-v1)`

## OS keychain (keytar)

| Field | Value |
|---|---|
| Service | `neos-work` |
| Account | `master-key` |
| Password payload | Base64 encoding of 32 raw key bytes |

- `get()`: missing/unloadable keytar or errors → `null`
- `set()`: keytar missing/fail → throws a clear error mentioning OS keychain / keytar
- Factory: `tryCreateOsKeychain(): OsKeychain | null` (never throws)

### Operator usage

```bash
# Prefer OS keyring; create key on first run if absent
export NEOS_SECRETS_KEY_BACKEND=os

# Or let auto pick OS when key already stored and keytar works
export NEOS_SECRETS_KEY_BACKEND=auto
```

Fallback when `keytar` is not installed or native binding fails:

- `backend=auto` → file keychain (if present) → legacy  
- `backend=os` → startup error (install `keytar` or use `env` / `file`)
