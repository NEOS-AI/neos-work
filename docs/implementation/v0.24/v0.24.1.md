# v0.24.1 Implementation — Track Web Workflow Editor

## Summary

Ship a **full web Workflow surface** matching desktop core editing capability:

- List / create / delete workflows
- React Flow graph editor (`@xyflow/react`)
- Palette (trigger, agent, output, gate_and, gate_or, web_search)
- Node config (label, agent `workerId`)
- Save via `PUT /api/workflow/:id`
- Run via `POST /api/workflow/:id/run` (SSE dry-path)

Not a clone of every desktop panel (revisions, domain pack tabs, run history UI, artifacts, etc.).

## Routes

| Path | Page |
|---|---|
| `/workflows` | List + create modal + delete |
| `/workflows/:id` | Graph editor |

Nav links added from Projects / Media / Settings.

## API client (`apps/web/src/lib/api.ts`)

| Method | HTTP | Notes |
|---|---|---|
| `listWorkflows()` | `GET /api/workflow` | throws `ApiError` on non-OK |
| `getWorkflow(id)` | `GET /api/workflow/:id` | rejects control-char ids |
| `createWorkflow({ name, domain?, nodes?, edges? })` | `POST /api/workflow` | envelope |
| `updateWorkflow(id, patch)` | `PUT /api/workflow/:id` | envelope |
| `deleteWorkflow(id)` | `DELETE /api/workflow/:id` | envelope |
| `listWorkflowRuns(id, limit?, offset?)` | `GET /api/workflow/:id/runs` | envelope on bad id |
| `runWorkflow(id, onEvent, inputs?)` | `POST /api/workflow/:id/run` | SSE; returns abort |

## Known limitations vs desktop

- No revision history / restore panel
- No domain-pack palette tabs or full worker catalog
- No run history panel, run inputs dialog, artifact preview
- No import/export zip/JSON UI
- No preflight panel, auto-layout, confirm-leave blocker
- Palette is a fixed minimal set (6 types)
- Node config is label + workerId only
