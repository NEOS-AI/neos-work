# v0.7.2 Implementation

## Summary

**M2 — Selection awareness.** Peers broadcast their current editing **path** and
**selector** on the collab channel (`selection.changed`). New joiners receive a
`selections[]` snapshot on `presence.sync`. Web and desktop publish on local
selection changes; `PresencePeersBar` shows path · selector under peer names and
a “N selecting” label.

## Protocol

| Event / API | Role |
|---|---|
| `selection.changed` | `{ selection: PeerSelection }` — path/selector (null clears) |
| `presence.sync.selections` | Snapshot for new joiners (excludes self) |
| `POST …/collab/selection` | `{ sessionId, path?, selector?, layerId? }` |
| `GET …/collab/selections` | Snapshot list |

`PeerSelection`:

```ts
{
  sessionId, displayName, colorHint,
  path: string | null,
  selector: string | null,
  layerId?: string | null,
  updatedAt
}
```

Paths use the same sanitizer as locks (no `..`, no control chars).  
Selectors: trim, max 400 chars, no control chars.

Fan-out: `selection.changed` is a CollabBus event (multi-node prep).

## Client UX

- Debounced (~120ms) publish when `selection` or open file path changes  
- `PresencePeersBar` `selections` map → avatar ring + popover subtitle  
- Label: `2 peers · 1 selecting` when at least one peer has a non-empty selection
