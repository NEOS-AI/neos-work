# v0.7.1 Implementation

## Summary

**M1 — Collab bus.** Pluggable transport for presence/lock fan-out across
processes: in-process **memory** (default) and **redis** (optional package +
URL, else documented stub). Local room state remains on each node;
`CollabBus` only carries join/leave/lock events.

## Config

| Env | Meaning |
|---|---|
| `NEOS_COLLAB_BUS` | `memory` (default) or `redis` |
| `NEOS_COLLAB_REDIS_URL` / `REDIS_URL` | `redis://` or `rediss://` when bus=redis |

```bash
# multi-node prep (install optional peer dep first: pnpm add redis -F @neos-work/server)
NEOS_COLLAB_BUS=redis NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 pnpm --filter @neos-work/server dev
```

Without `redis` package or URL → **redis-stub** (local fan-out only; status explains gap).

## Architecture

```text
SSE join ──► project-collab rooms/locks (local)
                │ broadcast fanout events
                ▼
            CollabBus.publish ──► other nodes
                │
                ▼
            applyRemoteCollabEvent ──► local SSE listeners
```

Fan-out event types: `presence.join|leave`, `lock.acquired|released`  
(not `presence.sync` — session-local)

## Limits (documented)

- Presence **membership** is still per-node (SSE connections are local).  
- Bus shares **events** and **lock snapshots** via remote apply; full multi-replica presence lists need a shared store (later).  
- Prefer **one replica** for accurate peer lists until M1+ shared presence store.
