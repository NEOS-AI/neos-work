# v0.5.28 Implementation

## Summary

**Task 1b residual — hash-based project file change detection after CLI runs.**
Post-CLI `run.files_changed` and project `file.changed` SSE no longer fire on
mtime-only touches; content SHA-256 (with size:mtime fallback) decides create
vs modify, and published events include `hash` when available.

기준: v0.5.27  
참고: Desktop/web already subscribe to project file SSE (v0.5.27). This hardens
the server-side publisher so agent rewrites of identical bytes (or touch-style
mtime bumps) do not thrash the Design Editor with false `disk-changed` events.

## Server

### `lib/project-files.ts`
- `ProjectFileSignature` — `{ size, mtimeMs, hash? }`
- `snapshotProjectFileSignatures(root, { hashContent, maxHashedFiles })` —
  lists files, hashes utf8 bodies under size cap (default ≤ 500 files)
- `projectFileSignatureChanged(before, after)` → `'created' | 'modified' | false`
  - both hashes present → compare hashes only
  - else fall back to size:mtime

### `routes/runs.ts` (`executeCliRun`)
- Before spawn: full content-hash snapshot of project files
- After spawn: re-snapshot; emit `run.files_changed` only when content (or
  size:mtime fallback) differs
- `publishProjectFileEvent` for created/changed paths includes `hash` +
  `source: 'agent'`
