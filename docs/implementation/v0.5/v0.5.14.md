# v0.5.14 Implementation

## Summary

**PLAN_FOR_V0_5_0 Task 8 foundation (M4 Media multi-provider).** Introduces a
provider catalog (≥4 families + stub), unified generate dispatch for
**image / audio / video**, async **video job** poll state machine, stub policy
default **off** (`NEOS_MEDIA_ALLOW_STUBS`), Settings multi-provider keys +
catalog status, MediaNode `mediaProvider` + video surface, and Media page
video kind filter.

기준: v0.5.13  
참고: OpenAI image/audio baseline pre-existed; this adds multi-provider + video.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/media/config` | surfaces + models + `providers[]` + `stubsAllowed` (no secrets) |
| GET | `/api/media/providers` | catalog with `configured` flags |
| POST | `/api/media/generate` | `surface: image\|audio\|video`, optional `provider` |
| GET | `/api/media/jobs/:id` | video job poll |
| GET | `/api/media/jobs` | recent jobs |
| POST | `/api/media/image` / `/audio` | accept optional `provider` |

### Video job lifecycle

```text
queued → running → succeeded | failed
```

Stub provider completes in-process immediately when stubs allowed.
