# v0.3.102 Implementation

## Summary

PLAN_FOR_V0_3_0 residual polish: **settings path-key hygiene**, **session
workspaceId query/create bounds**, **webhook workflowId via safeRouteId**,
**routine-scheduler id/cron/timezone sanitize**, **LLM ProviderRegistry

content**, **DeployNode/MediaNode SERVER_TOKEN drop**, and **isSafeHttpBaseUrl

## Changes

### Task 1: Settings / session / webhooks routes

- Settings GET/PUT/DELETE: shared `paramSettingKey` (alnum `._-`, max 100,
  control-char reject **before** trim)
- Session list: drop unsafe `workspaceId` query filter
- Session create: `workspaceId` via `safeRouteId`
- Webhooks / design-systems: path ids via `safeRouteId`
- `safeRouteId`: control-char reject before trim (so `\nevil` ≠ `evil`)
- `deleteSetting` / `isSafeHttpBaseUrl`: control-char + length bounds

### Task 2: Routine scheduler

- Sanitize routine id (≤100), cron expression (≤200), timezone (≤100)
- Control-char reject; bad timezone falls back to UTC
- Applied to schedule / run / addOrUpdate / remove / isRoutineRunning

### Task 3: LLM registry / deploy / media

- ProviderRegistry: provider id ≤50, model id ≤200; control-char reject
- Deploy lib: token ≤8k; deployment/account id caps; URL max 2k +
  control-char; content null-byte reject
- DeployNode: null-byte content reject; drop unsafe SERVER_TOKEN
- MediaNode: drop unsafe SERVER_TOKEN
- isValidDeployProjectName: explicit control-char reject

### Task 4: Unit tests

- Settings control-char/overlong keys (existing + route coverage)
- Registry control-char/overlong provider & model ids
- DeployNode null-byte content
- Deploy lib host URL / token / deploymentId
- Shared deploy project name control chars
- Scheduler control-char/overlong fields
- isSafeHttpBaseUrl control-char/overlong

### Task 5: Version

- monorepo **0.3.101 → 0.3.102**
- health / server banner / web_search User-Agent / MCP client version
