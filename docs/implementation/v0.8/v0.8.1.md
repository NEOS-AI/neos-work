# v0.8.1 Implementation

## Summary

**M1 — Redis presence registry.** Optional dual-write of peer membership to Redis
(SET + members set + TTL) so cold replicas can **hydrate** full peer lists on
join / REST, without depending only on bus event order. Defaults to in-process
when bus is memory; auto-enables when `NEOS_COLLAB_BUS=redis`.

기준: v0.8.0

## Config

| Env | Default | Meaning |
|---|---|---|
| `NEOS_COLLAB_PRESENCE` | `auto` | `auto` \| `memory` \| `redis` \| `off` |
| `NEOS_COLLAB_BUS` | `memory` | When `auto`, redis registry only if bus=`redis` |
| `NEOS_COLLAB_REDIS_URL` / `REDIS_URL` | unset | Redis connection |

```bash
# multi-replica (install optional: pnpm add redis -F @neos-work/server)
NEOS_COLLAB_BUS=redis \
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 \
pnpm --filter @neos-work/server dev
```

`auto` + bus=memory → no external registry (M0 memory membership only).  
`redis` without URL/package → **redis-stub** (documented; memory still works).

## Redis layout

| Key | Type | TTL |
|---|---|---|
| `neos:collab:presence:peer:{projectId}:{sessionId}` | string JSON peer | 270s |
| `neos:collab:presence:members:{projectId}` | set of sessionIds | 270s (refreshed) |

TTL matches `PRESENCE_REMOTE_IDLE_MS` (270s).

---

## Flow

```text
join local ──► membership memory ──► registry.put (async)
                │
SSE join ──► hydrateMembershipFromRegistry ──► memory remote upserts
                │
              presence.sync peers (local + redis-hydrated)
```
