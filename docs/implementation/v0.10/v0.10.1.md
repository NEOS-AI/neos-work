## Env

| Variable | Default | Meaning |
|---|---|---|
| `NEOS_COLLAB_LOCKS` | `auto` | Lock registry mode (same auto rule as presence: redis when bus=redis) |
| `NEOS_COLLAB_BUS` | `memory` | When `redis`, auto enables lock registry |
| `NEOS_COLLAB_REDIS_URL` / `REDIS_URL` | unset | Redis for bus + registries |

```bash
NEOS_COLLAB_BUS=redis \
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 \
NEOS_COLLAB_LOCKS=auto \
NEOS_SHARED_EDIT=1 \
  pnpm --filter @neos-work/server dev
```

## Redis keys

| Key | Type | TTL |
|---|---|---|
| `neos:collab:lock:{projectId}:{path}` | string JSON FileLock | ~270s |
| `neos:collab:locks:{projectId}` | set of paths | ~270s |

TTL refreshed on re-acquire and while the holder session is touched (SSE).

---

## Behavior

| Path | Behavior |
|---|---|
| Acquire / release | Dual-write put/del to registry; bus fan-out unchanged |
| `GET …/collab/locks` | Hydrate then list |
| Hard-enforce (PUT/DELETE/mkdir/restore) | Hydrate then `getFileLock` |
| SSE join | Hydrate locks before `presence.sync` |
| Remote `lock.*` bus events | Local mirror only (origin dual-wrote) |

### Safety (review fixes)

- Hydrate is **fill-missing only** (never overwrite local entry)
- Local release sets a short **tombstone** so registry lag cannot resurrect a lock
- Acquire/release **await** Redis dual-write
- Lock TTL refresh only on **heartbeat interval**, not every SSE tick
