# v0.16.0 Implementation — Track A

## Summary

**Track A — Settings + MCP client extract.** Moves settings, connection-test, and
MCP (servers, OAuth, Codex install, presets, TradingView CDP) off `EngineClient`
into `EngineSettingsClient`, matching the v0.12 hierarchy pattern.

Baseline: **0.15.x**  
Scope: desktop `apps/desktop/src/lib` only (no agent-runtime, server, e2e, inventory).

## Hierarchy

```text
EngineTransport
  → EngineProjectClient
    → EngineWorkflowClient
      → EngineSettingsClient   // NEW (v0.16 Track A)
        → EngineClient         // remaining domains
```

| Class | Role |
|---|---|
| `EngineTransport` | baseUrl, auth, headers, path segments |
| `EngineProjectClient` | design projects, collab, files, runs |
| `EngineWorkflowClient` | workflows, deploys, webhooks, blocks |
| `EngineSettingsClient` | settings, connection-test, MCP servers/OAuth/Codex |
| `EngineClient` | health, sessions, chat, agent, workspaces, skills, … |

Call sites keep `import { EngineClient, McpServerData } from '../lib/engine.js'`.
