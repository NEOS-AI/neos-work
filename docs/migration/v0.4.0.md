# Migrating to NEOS Work v0.4.0

This release is an intentional **breaking change** that makes **Domain Workers** a
first-class runtime unit and unifies workflow agent nodes under a single `agent`
type. Most v0.3.x data is upgraded **automatically** on load.

Plan reference: [`docs/plans/PLAN_FOR_V0_4_0.md`](../plans/PLAN_FOR_V0_4_0.md)

---

## Who is affected

| Surface | Impact |
|---|---|
| Saved workflows in SQLite | Auto-migrated to `schemaVersion: 2` on GET/list/run/import |
| Exported workflow JSON / ZIP | Load rewrites to v2; re-export to persist v2 |
| Templates | Shipped as v2 (`agent` + `workerId`) |
| Custom harnesses API | Prefer `/api/workers`; `/api/harness(es)` still works with deprecation headers |
| Desktop editor | Pack palette, Worker selector, coordinator mode, port warnings |
| Integrations parsing SSE | New optional `worker.*` and `node.warning` events |

---

## Automatic migration (v1 → v2)

On every server workflow load path (`rowToWorkflow`, create, update, import,
revision restore), `migrateWorkflowV1ToV2` runs:

1. `schemaVersion = 2`
2. `domain` → `primaryDomain` (DB column name `domain` is **unchanged**)
3. `agent_finance` → `type: 'agent'`, default `workerId: finance_analyst`
4. `agent_coding` → `type: 'agent'`, default `workerId: coding_reviewer`
5. `config.harnessId` → `config.workerId` (`workerId` wins if both set)
6. `config.provider` → `config.llmProvider` (`llmProvider` wins)
7. `domainPackIds` inferred from node workers when useful

API responses always return v2 graphs. Saving writes v2 only.

Desktop may show a one-time toast: *“Workflow converted to v2 (Domain Workers).”*

## Breaking changes checklist

### BC-1 — Unified agent node

| Before | After |
|---|---|
| `agent_finance`, `agent_coding` | `agent` + `config.workerId` |

Legacy types are still accepted on **load** (then rewritten). Do not emit
`agent_*` in new exports.

### BC-2 — `schemaVersion`

Documents should set `schemaVersion: 2`. Missing/1 is treated as v1 and migrated.

### BC-3 — Domain packs

| Before | After |
|---|---|
| `domain: finance \| coding \| general` | API/JSON: `primaryDomain: string` (+ optional `domainPackIds`) |
| Fixed enums everywhere | Built-in packs: finance, coding, research, general |

SQLite still uses column `domain` (value = primary pack id). Optional
`domain_pack_ids_json` stores multi-pack membership (since v0.4.2). Packs are
not a plugin SDK in v0.4 (built-in packs + custom workers only).

### BC-4 — Harness → Worker API

| Before | After |
|---|---|
| `GET/POST /api/harness` | `GET/POST /api/workers` |
| `AgentHarness` | `DomainWorker` (superset; `AgentHarness` type alias remains) |
| Table `custom_harness` | Table **`workers`** (+ `permission_profile`, `workspace_json`, `default_mode`) |

Compatibility (v0.4.x only; removal planned for v0.5):

- `GET /api/harness` and `GET /api/harnesses` → same handlers
- Response headers: `Deprecation: true`, `Link: </api/workers>; rel="successor-version"`
- Built-in worker **ids are stable** (`finance_analyst`, `coding_reviewer`, …)

New fields on workers:

- `permissionProfile`: `read_only` \| `read_write` \| `execute` \| `network` \| `full`
- `workspace`: `{ kind: 'none' \| 'run' \| 'isolated', subdir? }`
- `defaultMode`: `solo` \| `coordinator`

### BC-5 — SSE worker events

Additive events (clients that exhaustively switch event types must handle them):

```ts
| { type: 'worker.started'; nodeId; workerId; workerRunId }
| { type: 'worker.progress'; nodeId; workerRunId; chunk }
| { type: 'worker.completed'; nodeId; workerRunId; output }
| { type: 'worker.failed'; nodeId; workerRunId; error }
| { type: 'node.warning'; nodeId; message }  // ports / soft preflight
```

Run cancel propagates `AbortSignal` to child workers when using coordinator spawn.

### BC-6 — Gates

No rename. `gate_or` = logical OR; `or_gate` = race (first success). UI labels
clarify the difference.

### BC-7 — Agent config keys

Prefer `llmProvider` (and `workerId`). Legacy `provider` / `harnessId` migrate on load.

### BC-8 — Package exports

- `@neos-work/shared`: `DomainWorker`, `DomainPack`, `PortDef`, …
- `@neos-work/workflow-engine`: `resolveWorker` / `listWorkers` / `listPacks`,
  port helpers; harness names are aliases
- `@neos-work/core`: `WorkerRuntime` / `runWorker`, `createCoordinatorTools`

## Built-in Domain Packs (v0.4)

| Pack | Workers (ids) |
|---|---|
| **finance** | `finance_analyst`, `finance_risk`, `finance_chart_analyst`, `finance_portfolio` |
| **coding** | `coding_reviewer`, `coding_test_writer`, `coding_refactor`, `coding_implementer` |
| **research** | `research_web`, `research_synthesizer` |
| **general** | `general_generalist`, `general_coordinator` |

Coordinator is **not** a node type: use `type: 'agent'` + `config.mode: 'coordinator'`
(tools: `spawn_worker`, `await_workers`, `list_workers`). CLI providers are
disabled in coordinator mode.

## Typed ports MVP

Optional node config:

```ts
config.inputPorts?: PortDef[]
config.outputPorts?: PortDef[]
```

- Default: soft `node.warning` only
- Hard fail: set execution setting **`strictPorts=1`** (or `true` / `yes` / `on`)
- Editor shows yellow ⚠ on port type mismatch edges

## Manual steps (if any)

1. **Upgrade** monorepo / install v0.4.0 packages.
2. **Start the server** once so SQLite migrates `custom_harness` → `workers`.
3. **Open each workflow** (or re-import ZIPs) so graphs rewrite to v2; save if you
   keep offline exports.
4. **Update scripts** that called `/api/harness` to `/api/workers`.
5. **Update SSE clients** to ignore or render `worker.*` / `node.warning`.
6. Optionally set `strictPorts=1` in settings only after reviewing port warnings.

No manual graph editing is required for typical v0.3 finance/coding agent graphs.

---

## Rollback notes

- v0.4 always **writes** v2. Downgrading to v0.3 may reject `schemaVersion: 2`
  or unknown `agent` node types depending on age of the v0.3 build.
- Prefer keeping a DB backup (`~/.neos-work/data.db`) before upgrade if you must
  roll back.
