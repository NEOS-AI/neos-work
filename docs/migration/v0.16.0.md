# Migrating to NEOS Work v0.16.x

v0.16 is a **maintainability + multi-replica runs** train: desktop
`EngineClient` settings/MCP extract (Track A) and an optional shared **run
summary registry** for cross-pod GET/cancel (Track B). No product API breaks
from 0.15.x for single-process defaults.

Plan: [`docs/plans/PLAN_FOR_V0_16_0.md`](../plans/PLAN_FOR_V0_16_0.md)  
Parent: [`docs/migration/v0.15.0.md`](./v0.15.0.md)  
Release: [`docs/releases/v0.16.2.md`](../releases/v0.16.2.md)  
Ops multi-replica: [`docs/ops/multi-replica-collab.md`](../ops/multi-replica-collab.md)  
Sticky SSE (limits): [`docs/ops/sticky-sse.md`](../ops/sticky-sse.md)

> Treat monorepo **0.16.0–0.16.x** as the v0.16 line (see `docs/implementation/v0.16/`).  
> Closeout release: **0.16.2** (A0 + B0 + docs + inventory `v16Features`).

## Who is affected

| Surface | Impact |
|---|---|
| Desktop developers | Settings + MCP live on `EngineSettingsClient`; **import path unchanged** (`engine.js`) |
| Multi-replica operators | Optional **`NEOS_RUN_REGISTRY`** for cross-pod run GET/cancel (default `auto`) |
| Single-process / local | **Default behaviour unchanged** (memory summary mirror; local abort/events) |
| Workflows / SQLite / projects | **No data conversion** from 0.15.x |
| Auth / Docker / Helm | Prefer tags **≥ 0.16.2**; data under `NEOS_DATA_DIR` compatible |

## Track A — EngineClient hierarchy (developers)

```text
EngineTransport
  → EngineProjectClient
    → EngineWorkflowClient
      → EngineSettingsClient   // NEW (v0.16)
        → EngineClient
```

| Class | File | Role |
|---|---|---|
| `EngineTransport` | `engine-transport.ts` | baseUrl, auth, headers |
| `EngineProjectClient` | `engine-project.ts` | Design Project, collab, files, runs |
| `EngineWorkflowClient` | `engine-workflow.ts` | workflows, deploys, webhooks |
| `EngineSettingsClient` | `engine-settings.ts` | settings, connection-test, MCP |
| `EngineClient` | `engine.ts` | remaining domains + re-exports |


No call-site renames required for app code that already imports from `engine.js`.

## Track B — Shared run registry (operators)

Optional dual-write of **run summaries** (id, status, nodeId, projectId,
collabSessionId, timestamps) so multi-replica engines can answer
`GET /api/runs/:id` and `POST /api/runs/:id/cancel` when the live run is on
another process.

| Topic | Guidance |
|---|---|
| Local abort + events | Still **in-memory per process** (unchanged) |
| Shared summary | Dual-write via `NEOS_RUN_REGISTRY` |
| Event SSE | **Owner-local only** — no multi-node event fan-out in v0.16 |
| List runs | `GET /api/runs` still local-only |

Full detail: [ops multi-replica](../ops/multi-replica-collab.md) · [impl B0](../implementation/v0.16/v0.16.1.md).

### `NEOS_RUN_REGISTRY` modes

| Mode | Behaviour |
|---|---|
| `auto` (default) | Redis when collab bus is redis **or** Redis URL connects; else memory |
| `memory` | In-process summary map (single process / tests) |
| `redis` | Force Redis key + cancel channel |
| `off` | No dual-write — pre-v0.16 local-only behaviour |

```bash
NEOS_COLLAB_BUS=redis \
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 \
NEOS_RUN_REGISTRY=auto \
  pnpm --filter @neos-work/server dev
```

Status: `GET /api/collab/status` → `data.runs: { kind, ready, detail, nodeId }`.

## Environment

| Variable | Role |
|---|---|
| **`NEOS_RUN_REGISTRY`** | **New (optional)** — run summary store mode (`auto` \| `memory` \| `redis` \| `off`) |
| `NEOS_COLLAB_BUS` / `NEOS_COLLAB_*` | Multi-replica collab (unchanged) |
| `NEOS_SHARED_EDIT` / `NEOS_SHARED_EDIT_AGENTS` | Lock hard-enforce |
| `NEOS_DATA_DIR` | Durable root (projects, SQLite, media) |
| `NEOS_AUTH_TOKEN` | Shared secret across replicas |

Product E2E suite tiers (T0–T5) from v0.15 are unchanged.

---

## Upgrade checklist

1. From **0.15.x**: pull **≥ 0.16.2**; **no data migration scripts**.  
2. Desktop: rebuild; prefer `import … from '…/engine.js'` only (settings/MCP moved internally).  
3. Multi-replica: set `NEOS_RUN_REGISTRY=auto` (default) with working Redis for cross-pod GET/cancel; check `GET /api/collab/status` → `runs`.  
4. To restore pre-v0.16 local-only runs: `NEOS_RUN_REGISTRY=off`.  
5. Run `pnpm inventory:check` (requires `v16Features`).
