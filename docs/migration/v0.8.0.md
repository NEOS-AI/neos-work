# Migrating to NEOS Work v0.8.x

v0.8 is an **additive** train on top of v0.7 collab bus + Design Editor canvas.
**No automatic data conversion** is required. Workflows (schemaVersion 2),
Design Projects, skills/plugins, and local SQLite remain compatible.

Plan: [`docs/plans/PLAN_FOR_V0_8_0.md`](../plans/PLAN_FOR_V0_8_0.md)  
Parent: [`docs/migration/v0.7.0.md`](./v0.7.0.md)  
Security: [`docs/security/v0.5.md`](../security/v0.5.md) (still applies)  
ADR shared-edit: [`docs/adr/0001-shared-edit-strategy.md`](../adr/0001-shared-edit-strategy.md)

> Treat monorepo **0.8.0–0.8.x** as the v0.8 line (see `docs/implementation/v0.8/`).  
> Closeout release: **0.8.4** (docs + inventory gates).

---

## Who is affected

| Surface | Impact |
|---|---|
| Workflows / domain packs | **No change** |
| Design Projects / Editor | Additive: group canvas scale; multi-select collab awareness |
| Collab multi-node | **Shared presence membership** + optional Redis presence registry |
| Auth / Docker / Helm | Prefer tags **≥ 0.8.4**; single-replica still fine for local-first |
| CRDT / multi-caret | **Still out of scope** (Q19 / Q22) |

| Version | Feature |

## Environment flags

| Variable | Default | Meaning |
|---|---|---|
| `NEOS_COLLAB_BUS` | `memory` | `memory` \| `redis` — event fan-out |
| `NEOS_COLLAB_REDIS_URL` / `REDIS_URL` | unset | Redis for bus + presence (when enabled) |
| `NEOS_COLLAB_PRESENCE` | `auto` | `auto` \| `memory` \| `redis` \| `off` — membership registry |
| `VITE_NEOS_CANVAS_OVERLAY` / `NEOS_CANVAS_OVERLAY` | off | Canvas move / resize / multi / group scale |
| `NEOS_SHARED_EDIT` | off | Hard file-lock enforce on user **PUT** / **DELETE** / **revision restore** / **mkdir** when locked; identify holder via `sessionId` body and/or `x-neos-session-id`. Agent writes intentionally bypass ([ADR 0001](../adr/0001-shared-edit-strategy.md)) |
| `NEOS_AUTH_TOKEN` | (process random) | Unchanged — not logged in full when set via env |

```bash
# Multi-replica collab (optional redis package: pnpm add redis -F @neos-work/server)
NEOS_COLLAB_BUS=redis \
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 \
NEOS_COLLAB_PRESENCE=auto \
  pnpm --filter @neos-work/server dev

# Canvas overlay (web)
VITE_NEOS_CANVAS_OVERLAY=1 pnpm --filter @neos-work/web dev
```

**`NEOS_COLLAB_PRESENCE=auto`:** uses Redis registry when bus is `redis`; otherwise in-process membership only (M0).

## API additions (high level)

| Area | Paths / events |
|---|---|
| Collab status | `GET /api/collab/status` → `{ bus, nodeId, ready, detail, presence: { kind, ready, detail } }` |
| Presence membership | In-process store + bus join/leave/heartbeat (0.8.0) |
| Presence registry | Redis keys `neos:collab:presence:peer:{project}:{session}` + members set (0.8.1) |
| Selection multi | `POST …/collab/selection` body may include `selectors[]` / `layerIds[]` (0.8.3) |
| | SSE `selection.changed` may include `selection.selectors` |

## Upgrade steps

1. Deploy monorepo **≥ 0.8.4** (Docker image tag / Helm `appVersion`).  
2. Keep a stable `NEOS_AUTH_TOKEN` in secret/env.  
3. Single-node: no change required (defaults = memory bus + memory presence).  
4. Multi-replica: set `NEOS_COLLAB_BUS=redis`, Redis URL, install optional `redis` package.  
5. Optional: canvas overlay for group scale.  
6. Run CI gates:

```bash
pnpm inventory:check
pnpm e2e:smoke
# optional acceptance
pnpm e2e:c5
```

---

## Rollback

Point image/tag back to **0.7.4** or earlier **0.8.x**. User data under
`NEOS_DATA_DIR` is compatible. New env flags can remain unset.

|---|---|---|
