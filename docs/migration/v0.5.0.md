# Migrating to NEOS Work v0.5.x

v0.5 adds a **second first-class surface** — **Design Projects** with a
**Design Editor** (generate ↔ manual edit loop) — alongside the existing
Cowork-style **Workflow / Domain Workers** stack from v0.4. Most v0.4 data
continues to work **without conversion**.

Plan reference: [`docs/plans/PLAN_FOR_V0_5_0.md`](../plans/PLAN_FOR_V0_5_0.md)  
Security: [`docs/security/v0.5.md`](../security/v0.5.md)

> **Version note:** Feature work landed as incremental patches
> **0.5.0 → 0.5.x** (see `docs/implementation/v0.5/`). Treat any **0.5.x**
> monorepo release as “the v0.5 line” for migration purposes.

---

## Who is affected

| Surface | Impact |
|---|---|
| Saved **workflows** (schemaVersion 2) | **No change** — v0.4 model kept |
| `/api/workers`, domain packs, blocks | **Maintained** |
| New **Design Projects** | Additive: `/api/projects/*`, files, revisions, comments |
| Skills | Flat `*.md` still works; **`SKILL.md` packages** preferred |
| Desktop / Web / CLI | Three entry points to the same daemon |
| Harness aliases | `/api/harness(es)` still present with deprecation headers |

**There is no automatic workflow → design project conversion.** Use each surface
for its job (automation graph vs file-based design workspace).

---

## Dual surface (what to use when)

| Use **Workflow** when… | Use **Design Project** when… |
|---|---|
| Multi-step automation graphs, gates, workers | HTML/CSS (and friends) file workspace |
| Domain packs / finance·coding blocks | LLM generate → **Design Editor** edit → re-prompt |
| Scheduled routines on graphs | Live artifacts, media into a project folder |
| Coordinator `spawn_worker` fan-out | Folder import / archive export of a site |

Both share skills, design systems, memory, MCP, media, and the daemon auth token.

## Data layout

Default data root (unchanged family; env override):

```text
~/.config/neos-work/   or  $NEOS_DATA_DIR
├── data.db
├── projects/<id>/          # Design Project workspaces (new)
├── skills/                 # user skill overrides
├── design-systems/
├── plugins/
├── memory/
├── media/
├── domain-packs/           # custom Domain Pack installs (v0.5.22+)
└── workspaces/             # worker isolation (v0.4)
```

Imported folder projects may set `base_dir` to an absolute path (copy-free).

## Additive APIs (v0.5)

| Area | Paths (high level) |
|---|---|
| Projects / files / revisions | `/api/projects/*` |
| Runs (+ `editContext`) | `/api/runs/*` |
| Live artifacts | `/api/live-artifacts/*`, `/api/tools/live-artifacts/*` |
| Media multi-provider | `/api/media/*` |
| Plugins / atoms | `/api/plugins/*` |
| Connection test | `/api/connection-test` |
| **NEOS as MCP server** install | `/api/mcp/install-info`, `/api/mcp/install/codex*` |
| External MCP **clients** | `/api/mcp-servers` (existing) |
| Custom domain packs | `/api/domain-packs` install/toggle |

Workflow routes under `/api/workflow` remain the source of truth for graphs.

## Breaking / behaviour changes

### B1 — Harness → Workers (from v0.4, still true)

Prefer `/api/workers`. `/api/harness` and `/api/harnesses` stay as aliases with
`Deprecation` headers.

### B2 — Skills discovery precedence

1. Project-private skills  
2. User (`$NEOS_DATA_DIR/skills`)  
3. Bundled repo `skills/`

Package form: directory with `SKILL.md` (+ optional assets/references/examples).
Flat `*.md` remains supported.

### B3 — Media stubs off by default

Image/audio/video stub providers require `NEOS_MEDIA_ALLOW_STUBS=1`.

### B4 — Tool tokens cannot override project scope

`/api/tools/*` derives `projectId` from the tool token only; body overrides → 403.

### B5 — Design Editor defaults (Q9–Q13)

| Lock | Behaviour |
|---|---|
| CodeMirror 6 | Default code engine (not Monaco) |
| Patch-first AI | `editContext.mode` defaults to `replace-selection` / `patch` |
| No free-canvas | Layers tree yes; drag-resize canvas no |
| BYOK + tools | Default generate path; CLI agents opt-in |

### B6 — Domain Pack custom loader

Custom packs use schema `neos-domain-pack/v1`. Built-in pack ids
(`finance` / `coding` / `research` / `general`) are reserved. Custom packs may
only declare **prompt/skill** blocks (no native executors).

## Manual upgrade steps

1. **Backup** `~/.config/neos-work/data.db` (and project folders if any).
2. **Upgrade** monorepo / install packages to latest **0.5.x**.
3. **Start the daemon** once so additive SQLite migrations run.
4. **Optional:** open Design Projects in the desktop/web UI; create a project and
   open the Design Editor (Preview / Code / Layers).
5. **Optional:** install `neos` CLI and run `neos doctor` / `neos mcp install-info`.
6. **Optional:** `pnpm inventory --check` to verify bundled capability gates.
7. Update scripts that assumed desktop-only: web + Docker + CLI are supported.

No forced rewrite of schemaVersion 2 workflows.

neos daemon start

neos project list

neos doctor

## Rollback notes

- v0.5 writes **additive** tables; rolling back to pure v0.4 leaves unused tables
  but keeps workflow rows.
- Design Project files under `projects/` are not deleted on downgrade.
- Custom domain-packs under `domain-packs/` are ignored by pre-Task-15 builds.
