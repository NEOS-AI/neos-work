# Migrating to NEOS Work v0.6.x

v0.6 is an **additive** train on top of v0.5 Design Projects + dual surface.
No automatic data conversion is required. Workflows (schemaVersion 2) and
local skills/plugins continue to work.

Plan: [`docs/plans/PLAN_FOR_V0_6_0.md`](../plans/PLAN_FOR_V0_6_0.md)  
Security: [`docs/security/v0.5.md`](../security/v0.5.md) (still applies; collab notes in ops below)

> Treat monorepo **0.6.0–0.6.x** as the v0.6 line (see `docs/implementation/v0.6/`).

---

## Who is affected

| Surface | Impact |
|---|---|
| Workflows / domain packs | **No change** |
| Design Projects / Editor | Additive: presence, locks, JSX layers, optional canvas |
| Plugins | Additive: remote catalog install into user skills |
| Auth / Docker | Token not printed when set via env; Helm snippet optional |
| Multi-replica | **Not supported** for collab (in-process presence/locks) |

## Environment flags

| Variable | Default | Meaning |
|---|---|---|
| `NEOS_AUTH_TOKEN` | (process random) | When set from env, value is **not** logged in full |
| `NEOS_SHARED_EDIT` | off | `1` → HTTP 423 if writing a file locked by another session |
| `VITE_NEOS_CANVAS_OVERLAY` / `NEOS_CANVAS_OVERLAY` | off | Design Editor drag overlay on HTML preview |
| `marketplace.catalogUrl` | unset | Setting (API), not env — remote catalog HTTPS URL |

## Upgrade steps

1. Deploy monorepo **≥ 0.6.5** (Docker image tag / Helm `appVersion`).  
2. Keep a stable `NEOS_AUTH_TOKEN` in secret/env (not logs).  
3. Optional: set remote catalog via Desktop **Plugins → Remote catalog** or  
   `PUT /api/marketplace/catalog-url`.  
4. Optional: enable canvas / shared-edit flags only if you need them.  
5. Run `pnpm inventory:check` and `pnpm e2e:smoke` in CI.

---

## Rollback

Point image/tag back to last 0.5.x or earlier 0.6.x. User data under
`NEOS_DATA_DIR` is compatible. Remote-installed plugins remain as local
`skills/<id>/open-design.json` files.
