## Highlights for operators

### Multi-replica locks

With `NEOS_COLLAB_BUS=redis` and `NEOS_COLLAB_LOCKS=auto` (default when bus is redis):

- Acquire/release dual-writes Redis (`neos:collab:lock:…`)
- Hard-enforce and lock list **hydrate** from the registry (fill-missing; local release tombstones)
- Status: `GET /api/collab/status` → `data.locks.{kind,ready,detail}`

See [ops multi-replica collab](../ops/multi-replica-collab.md).

### Agent lock enforce (opt-in)

```bash
NEOS_SHARED_EDIT=1 \
NEOS_SHARED_EDIT_AGENTS=1 \
  pnpm --filter @neos-work/server dev
```

Default remains agent bypass under human locks (edit-with-AI).

### Breaking: harness HTTP (0.10.2+)

`/api/harness` and `/api/harnesses` return **410 Gone**. Use **`/api/workers`**.

### Still out of scope

- Full **CRDT** multi-caret  
- Sticky SSE across replicas  
- Multi-tenant RBAC  
- Run → sessionId bind for agents (optional future)

## Upgrade checklist

1. Point scripts off `/api/harness*` → `/api/workers`.  
2. Multi-replica: set shared `NEOS_AUTH_TOKEN`, Redis URL, `NEOS_COLLAB_BUS=redis`.  
3. Optional: enable `NEOS_SHARED_EDIT` / `NEOS_SHARED_EDIT_AGENTS` / inspect `collab/status`.  
4. Run `pnpm inventory:check` in CI.

No automatic SQLite / workflow migration required from 0.9.x.
