## Highlights for operators

### Multi-replica collab (optional)

v0.8 hardens **peer membership across engine replicas** on top of the v0.7
event bus:

| Concern | Default (local-first) | Multi-replica |
|---|---|---|
| Event fan-out | In-process memory bus | `NEOS_COLLAB_BUS=redis` + Redis URL |
| Peer lists | In-process membership (M0) | Bus-mirrored remotes + optional Redis TTL registry (M1) |
| SSE | Always **local to the node** that holds the connection | Same — no sticky-session requirement for presence lists if registry is used |
| File locks / disk | Single-writer lock + LWW (unchanged) | Same model; prefer shared `NEOS_DATA_DIR` / one writer surface |

Key env (full detail in [ops guide](../ops/multi-replica-collab.md)):

```bash
NEOS_COLLAB_BUS=redis
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379   # or REDIS_URL
NEOS_COLLAB_PRESENCE=auto                       # redis registry when bus=redis
```

Optional Node package: `redis` on `@neos-work/server`. Without package or URL,
bus/registry fall back to **redis-stub** (local-only fan-out; status explains why).

Deploy entrypoints:

- Docker Compose: [deploy/README.md](../../deploy/README.md) (single process by default)
- Helm single-replica chart: [deploy/helm/neos-work](../../deploy/helm/neos-work)
- Multi-replica Redis setup: [docs/ops/multi-replica-collab.md](../ops/multi-replica-collab.md)

Auth / data: keep a stable `NEOS_AUTH_TOKEN`; SQLite + media under `NEOS_DATA_DIR`
remain compatible with **0.7.x** and earlier **0.8.x** (no auto migration).

### Status probe

```http
GET /api/collab/status
```

Returns bus kind/nodeId/ready plus `presence: { kind, ready, detail }` so ops
can confirm Redis vs memory vs stub before opening multi-client sessions.

### Still out of scope

- Full **CRDT** multi-caret  
- **Sticky SSE** across replicas  
- Multi-tenant RBAC

## Rollback

`NEOS_DATA_DIR` is compatible. New env flags can remain unset (defaults stay
local-first memory bus + memory presence).
