## Highlights for developers

### Desktop hierarchy (A0)

```text
EngineTransport → EngineProjectClient → EngineWorkflowClient
  → EngineSettingsClient → EngineClient
```

Public imports stay:

```ts
import { EngineClient, McpServerData } from '../lib/engine.js';
```

```bash
pnpm --filter @neos-work/desktop exec vitest run src/lib/engine.test.ts
```

### Shared run registry (B0)

```bash
NEOS_COLLAB_BUS=redis \
NEOS_COLLAB_REDIS_URL=redis://127.0.0.1:6379 \
NEOS_RUN_REGISTRY=auto \
  pnpm --filter @neos-work/server dev
```

| Path | Behaviour |
|---|---|
| `GET /api/runs/:id` | Local first; else shared summary |
| `POST /api/runs/:id/cancel` | Local cancel, or publish cancel + mark canceled |
| Event SSE | Unchanged — owner-local |

Default single-process path remains green for contract/journey/browser e2e.

```bash
pnpm e2e:contract
pnpm e2e:journey
pnpm e2e:browser
```

### Inventory

```bash
pnpm inventory:check
```

run registry shared, impl A + B, multi-replica ops doc).

## Upgrade checklist

1. From **0.15.x**: no data migration.  
2. Desktop: no import renames if you use `engine.js`.  
3. Multi-replica: keep `NEOS_RUN_REGISTRY=auto` with Redis for cross-pod cancel; or `off` for local-only.  
4. `pnpm inventory:check`.

No automatic SQLite / workflow migration required from 0.15.x.
